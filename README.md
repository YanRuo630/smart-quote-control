# 🎯 智能引用回复控制插件 (smart-quote-control)

一个专门用于优化 MaiBot 引用回复行为的辅助插件。它能根据聊天环境（私聊/群聊）、消息密度和回复延迟**智能判断**是否需要引用回复，让 Bot 的回复更加自然、符合人类聊天习惯。

---

## ✨ 核心特性

- 🔇 **私聊智能禁用**：私聊场景默认不引用回复，让一对一对话更自然流畅，避免冗余的引用标记。
- 🧠 **群聊智能判断**：群聊中根据**消息密度**和**回复延迟**双重条件智能决策：
  - **消息密度判断**：艾特后如果有大量消息插入（默认 ≥3 条），则引用回复帮助定位上下文。
  - **延迟判断**：回复延迟超过阈值（默认 30 秒）时强制引用，防止用户忘记聊天内容。
- ⚫⚪ **黑白名单支持**：
  - **白名单**：指定群号始终启用引用回复。
  - **黑名单**：指定群号始终禁用引用回复。
- 🔧 **灵活配置**：支持 WebUI 可视化配置和 `config.toml` 手动编辑，支持配置热更新（Hot Reload）。
- 📊 **详细日志**：提供完整的调试日志，方便排查问题和调整参数。

---

## 🛠️ 实现原理

本插件基于 **MaiBot SDK 2.0** 架构开发，利用了全新的 **Hook 处理器**机制。

### Hook 处理流程

1. **消息记录阶段**（`chat.receive.before_process`）
   - 记录群聊中的每条消息时间戳。
   - 检测艾特消息并记录艾特时间。
   - 在 `HookOrder.EARLY` 阶段执行，确保最早捕获消息。

2. **引用控制阶段**（`send_service.after_build_message`）
   - 在消息发送前拦截，检查是否需要引用回复。
   - 根据聊天类型（私聊/群聊）执行不同的判断逻辑。
   - 群聊场景下统计艾特后的消息数量和回复延迟时间。
   - 根据配置的阈值决定是否保留或移除引用组件。
   - 在 `HookOrder.LATE` 阶段执行，确保在其他插件（如智能分段）之后处理。

### 判断逻辑

**私聊场景**：
```
私聊消息 → 直接禁用引用
```

**群聊场景**：
```
检查黑白名单 → 黑名单：禁用引用
              → 白名单：强制引用
              → 其他：智能判断

智能判断 → 回复延迟 ≥ 30秒？ → 是：强制引用
                              → 否：检查消息数

消息数判断 → 艾特后消息数 ≥ 3条？ → 是：启用引用
                                  → 否：禁用引用
```

## ⚙️ 配置文件说明 (`config.toml`)

本插件支持在 WebUI 面板中直接可视化修改配置。其生成的配置文件位于插件目录下的 `config.toml`，内容格式如下：

```toml
[plugin]
# 配置文件版本
config_version = "1.0.0"

# 是否启用插件
enabled = true

# 私聊环境下禁用引用回复，让一对一对话更自然
disable_quote_in_private = true

# 群聊中根据消息密度和回复延迟智能判断是否需要引用
enable_smart_quote_in_group = true

# 消息数量阈值：艾特后到回复前的消息数达到此值时才引用（范围 1-20）
group_message_threshold = 3

# 时间窗口：统计消息的时间范围，单位秒（范围 10-300）
group_time_window = 60

# 延迟阈值：回复延迟超过此时间（秒）则强制引用，防止用户忘记上下文（范围 5-120）
reply_delay_threshold = 30

# 被艾特时强制引用回复，无视消息数和延迟判断
force_quote_when_at = false

# 白名单群号：这些群始终启用引用回复，多个群号用英文逗号分隔，留空表示应用到所有群
# 例如: whitelist_groups = "123456,789012"
whitelist_groups = ""

# 黑名单群号：这些群始终禁用引用回复，多个群号用英文逗号分隔
# 例如: blacklist_groups = "123456,789012"
blacklist_groups = ""
```

---

## 📖 配置参数详解

### 基础设置

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `enabled` | bool | `true` | 是否启用插件 |
| `disable_quote_in_private` | bool | `true` | 私聊中禁用引用回复 |
| `enable_smart_quote_in_group` | bool | `true` | 群聊中启用智能判断 |

### 智能判断参数

| 参数 | 类型 | 默认值 | 范围 | 说明 |
|------|------|--------|------|------|
| `group_message_threshold` | int | `3` | 1-20 | 消息数量阈值 |
| `group_time_window` | int | `60` | 10-300 | 消息统计时间窗口（秒） |
| `reply_delay_threshold` | int | `30` | 5-120 | 回复延迟阈值（秒） |

### 高级设置

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `force_quote_when_at` | bool | `false` | 被艾特时强制引用（无视智能判断） |
| `whitelist_groups` | str | `""` | 白名单群号（逗号分隔） |
| `blacklist_groups` | str | `""` | 黑名单群号（逗号分隔） |

## 🎬 使用场景示例

### 场景 1：快速回复，消息少
```
10:00:00 - 用户: @Bot 今天天气怎么样
10:00:02 - Bot: 今天晴天，温度 25°C
```
**判断**：延迟 2 秒 < 30 秒，消息 0 条 < 3 条 → **不引用**

### 场景 2：快速回复，消息多
```
10:00:00 - 用户: @Bot 今天天气怎么样
10:00:01 - 用户A: 我觉得会下雨
10:00:02 - 用户B: +1
10:00:03 - 用户C: 确实
10:00:05 - Bot: 今天晴天，温度 25°C
```
**判断**：延迟 5 秒 < 30 秒，消息 3 条 ≥ 3 条 → **引用回复**

### 场景 3：慢速回复，消息少
```
10:00:00 - 用户: @Bot 帮我写一篇文章
10:00:40 - Bot: 好的，我来写...
```
**判断**：延迟 40 秒 > 30 秒 → **强制引用**（防止用户忘记上下文）

### 场景 4：私聊对话
```
10:00:00 - 用户: 你好
10:00:02 - Bot: 你好！有什么可以帮你的吗？
```
**判断**：私聊场景 → **不引用**

## 🚀 安装使用

### 前置要求

⚠️ **重要**：使用本插件前，请确保 MaiBot 原生的引用回复功能已开启：

1. 进入 MaiBot 配置文件 `config/config.toml`
2. 找到 `[chat]` 部分
3. 确保 `enable_reply_quote = true`（默认值）

```toml
[chat]
enable_reply_quote = true  # 必须为 true，否则插件无法工作
```

**说明**：本插件是在 MaiBot 原生引用功能的基础上进行**智能控制**，如果原生功能关闭，插件将完全失效。

### 安装步骤

1. 将本插件文件夹放入 MaiBot 的 `plugins/` 目录下。
2. 启动或重启 MaiBot，插件会自动被加载。
3. （可选）进入 WebUI → 插件管理 → 智能引用回复控制 → 调整配置参数。

## 🐛 故障排查

### 问题：插件不生效
1. 检查插件是否已启用：`enabled = true`
2. 查看 MaiBot 日志，搜索 "智能引用回复控制"
3. 确认 MaiBot 原生的 `enable_reply_quote` 没有被关闭

### 问题：私聊仍然引用
1. 确认 `disable_quote_in_private = true`
2. 检查是否有其他插件强制启用了引用
3. 查看日志是否有 "私聊禁用引用回复" 输出

### 问题：群聊判断不准确
1. 查看日志中的统计信息：
   ```
   群 278612103 智能判断: 艾特后消息数=2, 阈值=3, 回复延迟=5.2秒, 延迟阈值=30秒, 是否引用=False
   ```
2. 调整 `group_message_threshold` 或 `reply_delay_threshold`
3. 调整 `group_time_window` 时间窗口

### 问题：与智能分段插件冲突
本插件使用 `HookOrder.LATE` 确保在智能分段之后执行。如果仍有冲突：
1. 查看两个插件的加载顺序
2. 检查日志中两个插件的 Hook 执行顺序
